01 - PROJECT OVERVIEW
=====================================================================
Goal
  A TurtleBot3 (differential drive, 2D LiDAR + camera) in MuJoCo drives
  through a room with 3 circular obstacles, follows 4 waypoints, then
  docks visually to an ArUco marker (ID 0, DICT_4X4_50) at the charging
  station. Hardware demo reuses the same pipeline.

Hard constraint
  The controller uses the ESTIMATED pose only. Ground truth is logged
  for evaluation only.

Data flow (per 0.02 s control step, 50 Hz)
  simulation -> sensing.py + calibration.py (odometry, LiDAR, marker
  range/bearing/view angle) -> estimator.py (EKF predict + update)
  -> navigation.py (TRACK/AVOID) -> docking.py (visual servoing)
  -> controller.py (LQR, limits) -> robot moves -> sensors measure again.
  main.py is the state machine (NAVIGATE -> DOCK -> DONE/FAILED).

Demo success criteria
  1. Pipeline runs end to end without crashing.
  2. No collision, finishes before the 120 s limit.
  3. Final pose: range 0.40 +/- 0.05 m from marker, lateral error
     < 0.06-0.08 m, heading error < 0.2 rad.
  4. Controller input is the EKF estimate (tests confirm this).
  5. Numbers shown come from a logged run of the submitted code.

02 - THEORY CHEAT SHEET
=====================================================================

2.1 Differential-drive kinematics  (robot_model.py)
  Meaning : how the pose [x y theta] changes with inputs [v w].
  Core    : ds = r*(dphiR + dphiL)/2,  dtheta = r*(dphiR - dphiL)/L
            x' = x + ds*cos(theta + dtheta/2)
            y' = y + ds*sin(theta + dtheta/2)
            theta' = theta + dtheta
  Why     : it is the prediction model of the EKF and the plant of the
            LQR. Parameters: r = 0.033 m, L = 0.287 m.

2.2 State-space, controllability, observability  (robot_model.py)
  Meaning : which states can be steered and which can be inferred.
  Core    : e[k+1] = A e[k] + B du[k];  controllable if rank[B AB A^2B]=n
            observable if rank[H; HA; HA^2]=n
  Result  : rank 3/3 while moving, 2/3 when stopped (both).
  Why     : the system is not fully controllable/observable at standstill,
            so the model analysis must state the operating condition.

2.3 Camera model, calibration, coordinate frames  (calibration.py)
  Meaning : how pixels relate to metric rays; how camera, robot and
            world frames connect.
  Core    : u = fx*X/Z + cx, v = fy*Y/Z + cy; K = [[fx 0 cx],[0 fy cy],
            [0 0 1]]; fx = (H/2)/tan(fovy/2) = 415.7 px (640x480, 60 deg)
            p_robot = R*p_cam + t (camera offset 0.23 m forward)
  Why     : marker range/bearing must be expressed in the robot frame
            before the EKF uses them.

2.4 LiDAR processing and measurement models  (sensing.py)
  Meaning : turn raw data into usable measurements.
  Core    : 360 beams, 0.12-3.5 m, sigma 0.01 m; point = r*[cos a, sin a];
            marker: z = [range, bearing, view_angle] from ArUco pose
  Why     : LiDAR gives free-space for avoidance; marker gives the
            absolute correction for the EKF and the docking error.

2.5 EKF, covariance, innovation  (estimator.py)
  Meaning : fuse odometry (prediction) with marker range/bearing (update).
  Core    : x- = f(x, ds, dtheta);  P- = F P F^T + Q
            nu = z - h(x-);  S = H P- H^T + R;  K = P- H^T S^-1
            x = x- + K nu;  P = (I - K H) P-
            h(x) = [ sqrt(dx^2+dy^2),  atan2(dy,dx) - theta ]
            (bearing innovation wrapped to [-pi, pi])
  Why     : odometry drifts; a single known landmark bounds the drift.
  Config  : P0 std 0.05; Q std 0.01 per step; R std (0.02 m, 0.01 rad).

2.6 LQR feedback control  (controller.py)
  Meaning : optimal state feedback on the tracking error.
  Core    : minimise sum(e^T Q e + du^T R du);  du = -K e
            Q = diag(10,10,1), R = diag(1,1); K from the discrete Riccati
            equation; commands clipped to v <= 0.26 m/s, |w| <= 1.82 rad/s
  Why     : gives stable, tunable tracking; closed-loop max |pole| = 0.988
            (<1, stable).

2.7 Obstacle avoidance and goal tracking  (navigation.py)
  Meaning : reach waypoints without collision using only LiDAR.
  Core    : free-corridor test of half-width (body_radius + margin) and
            length 0.6 m; pick the free heading nearest the goal with a
            hysteresis cost; TRACK <-> AVOID with an exit delay.
  Why     : reactive and cheap; known weakness is local minima.

2.8 Visual servoing  (docking.py)
  Meaning : steer from the marker observation until aligned with it.
  Core    : v = clip(K_range*(range - 0.40), 0.03, 0.12) scaled down for
            large bearing/axis error
            w = (K_bearing + K_axis)*bearing - K_axis*view_angle
            docked if range <= 0.45, |bearing| <= 0.05, |axis| <= 0.10
            axis = bearing - view_angle
  Why     : the camera error is the most direct signal for alignment.

2.9 FSM, integration, safety  (main.py, navigation.py)
  Meaning : phases and failure handling.
  Core    : NAVIGATE -> DOCK -> DONE | FAILED; docking sub-states
            SEARCH, APPROACH, ALIGN, DOCKED, FAILED; collision and
            timeout checks; invalid estimate -> stop.
  Why     : makes behaviour predictable and failures diagnosable.

2.10 RMSE, NEES, NIS, robustness  (main.py, estimator.py)
  Meaning : evidence that the estimator is accurate AND honest.
  Core    : RMSE = sqrt(mean(|e|^2)); NEES = e^T P^-1 e (expect ~3 for
            3 states); NIS = nu^T S^-1 nu (expect ~2); chi-square gate
            9.21 (99%, 2 DoF)
  Why     : a small error with an over-confident P is still a bad filter.

05 - DEMO AND VIVA Q&A (short answers)
=====================================================================
Q1. What is the state and what are the inputs?
  A: State [x, y, theta]; inputs [v, w]. Differential drive with
     midpoint-integrated odometry.

Q2. Is the system controllable and observable?
  A: Yes while moving (rank 3/3). When stopped, both ranks drop to 2/3,
     so heading is not recoverable from a single landmark at standstill.

Q3. Why an EKF and not a linear KF?
  A: The motion model (sin/cos of theta) and the range-bearing model
     (sqrt, atan2) are nonlinear; the EKF linearises them with Jacobians.

Q4. What does the EKF fuse?
  A: Wheel odometry in the prediction step; marker range and bearing
     from the camera in the update step.

Q5. How did you choose Q and R?
  A: Currently from the sensor noise settings in the config, not from
     measured data. NEES showed the filter was over-confident, so
     re-tuning is the planned next step. (Be honest about this.)

Q6. How do you know the filter is consistent?
  A: NEES (expected ~3) and NIS (expected ~2). Our logged NEES is
     [value from run], so [consistent / over-confident].

Q7. Does the controller use ground truth?
  A: No. It uses the EKF estimate only. A test replaces ground truth
     with garbage and the run is unchanged.

Q8. Are the camera parameters calibrated?
  A: No. They are nominal MuJoCo intrinsics. The calibration routine
     exists and is tested on synthetic views; real-image calibration
     and reprojection error are pending.

Q9. Why LQR, and how were the weights chosen?
  A: LQR gives stable optimal feedback on the linearised tracking error.
     Q = diag(10,10,1), R = I give max |pole| 0.988. Weights have not
     been swept yet; a sweep is planned.

Q10. How does navigation avoid obstacles, and what are its limits?
  A: It checks free corridors from LiDAR and picks the free heading
     nearest the goal, with hysteresis. It is reactive, so it can get
     trapped in local minima; we saw this and fixed it with waypoints
     and an AVOID exit delay.

Q11. How does docking work?
  A: Visual servoing: speed from range error, steering from bearing and
     the marker view angle. It is docked when range, bearing and axis
     error are inside tolerance.

Q12. What happens if the marker is lost?
  A: Docking propagates the last measurement with odometry for 0.5 s,
     then searches by rotating; it fails after the search timeout.
     Robust recovery is a future enhancement.

Q13. What are the known limitations?
  A: Nominal calibration, untuned Q/R, no Monte Carlo statistics yet,
     no back-off-and-retry in docking, hardware not yet validated.
